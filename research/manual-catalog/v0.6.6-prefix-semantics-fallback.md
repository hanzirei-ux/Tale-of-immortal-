# Tale of Immortal Android — Manual Prefix v0.6.6

**Status:** Read-only research; DEX Mod Menu v0.3.6 unchanged. No APK, proprietary game binaries or private save data are committed. Rarity excluded.

## Key new finding: prefix IDs are semantically linked

The v0.6.5 static mapping is now corroborated by the original **native write path**.

- In `MartialData.SetPrefixID` (`0x40a45c4`), input register `w22` is used as the `number` argument to `ConfBattleSkillPrefixValue.GetItem` (`bl 0x52c2acc` at `0x40a4668`).
- The same `w22` is written into the manual's array using `bl 0x40a2440` at `0x40a4684`. The setter's actual integer store occurs at `0x40a2460`.
- `ConfBattleSkillPrefixValue.GetItem` searches the full key `(SkillType, BaseID, Number)` first (`0x52c2b74`), then falls back to `(SkillType, 0, Number)` (`0x52c2b90`). Another fallback exists but is unnecessary for the 515 observed triples.

The 198 formerly unresolved combinations are all prefix numbers 1–5 for Skill Types 1, 2 and 5. Fifteen empty-`skillID` config rows provide the fallback `(SkillType, 0, Number)` keys, explaining those missing matches.

### Example
`(SkillType=1, BaseID=12111, Number=2)` resolves via generic config `(1,0,2)`, rather than a specialized config keyed to that BaseID.

## Limits

- These are **static configuration** and save-vector results. They do not establish that a newly generated manual can be added to inventory, or that a live Java/JNI bridge exists.
- No final names or displayed Level values have been reconstructed for the 183 instances. Raw prefix numeric slots are not display Level.
- The 92 multi-ID arrays are statically linked through ELF relocs and IL2CPP metadata (v0.6.5); live runtime FieldInfo state has not been observed.
- DEX Mod Menu v0.3.6 and all working gameplay cheats remain unchanged.
