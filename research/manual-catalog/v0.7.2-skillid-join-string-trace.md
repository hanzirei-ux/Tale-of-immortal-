## New verified mechanism

We have resolved the string literal and the array-join helper previously obstructing `GetTotalValue` name reconstruction:

1. `GetTotalValue` at `0x52c0f78` retrieves `ConfBattleSkillPrefixValueItem.skillID` through the field at `+0x20` (`0x52c11d0`).
2. The helper call at `0x52c11ec` targets `0x6c8821c`. Its second input is a string literal read through a **GOT relocation**:
   - GOT location: `0x802f230`
   - Relocation target: `0x878cf50`
   - Tagged IL2CPP literal: `0xa0088307`
   - `global-metadata.dat` string-literal index: **278915**
   - Verified text: **`|`**
3. The helper traverses the supplied array/enumerable in order, appends the first element (`0x6c88428`), then appends separator (`0x6c885bc`) and subsequent element (`0x6c885cc`), returning a string through a virtual call (`0x6c885e4`). This matches a pipe-delimited string join.
4. After calling the helper, the caller invokes a virtual string conversion at `0x52c11fc` and appends the result to its working string at `0x52c120c`.
5. The working string begins with the value returned by `MartialData` getter `0x40a44d0`, which selects `values[4]` (`0x40a44d8`). The independently decoded inventory schema identifies `values[4]` as **Base ID**.

Thus an *illustrative* three-element ID array would be formatted as `12111|12112|12113`. It is **not** a manual title, and this report does **not** claim a complete reconstructed selector input.
