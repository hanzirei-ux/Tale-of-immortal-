# Tale of Immortal — v0.7.3, Manual Name Selector Numerical Checksum

**2026-11-01 · Read-only analysis.** No DEX, APK, native libraries, JNI4 bridge, game save, or existing Mod Menu cheat feature changed. Rarity excluded.

## Main breakthrough

We traced the character-to-integer conversion at `0x76d04c0` used by `ConfBattleSkillPrefixName.GetTotalValue` (`0x52c0f78`).

- The UTF-16 code unit for each character comes from `0x75624dc` (call at `0x52c1404`) and is masked to 16 bits.
- The code unit is converted to a **decimal string** by the integer formatting wrapper `0x76d0190` (call at `0x52c1418`).
- The string is then parsed by `0x76d04c0` (call at `0x52c142c`). It invokes the integer parser with `NumberStyles.Integer = 7` (at `0x76d056c` and branch to `0x76cf5c0` at `0x76d057c`).
- The game applies absolute value and accumulates the parsed number (`0x52c145c`–`0x52c146c`).

**Thus the numeric checksum counts UTF-16 code units, NOT the decimal value of each digit.** In this ASCII-only observed configuration, '0' contributes **48**, '9' **57**, '|' **124**, and '-' **45**. For example, the test fixture `0|9` contributes 229, not 9.

### Candidate input construction

The original ARM64 trace supports the following read-only reconstruction, provided the configuration and save collection order match runtime:

1. Start with `MartialData.values[4]` (Base ID) as its decimal string.
2. For a group argument `g`, repeat **g times** the list of prefix configuration contributions in order. Each row contributes decimal `skillType` + the `skillID` integer array joined with **`|`** + decimal `number*123`. `GetName` calls `GetTotalValue` with **g=3** and **g=5**.
3. Append the ordered second pass: `number*(prefixPosition+2)` for each prefix, as decimal text.
4. Add the UTF-16 numeric code units of the final string.
5. The first name-list index is `(checksum3 * 123) % 200`, and the second is `(checksum5 * 456) % 200`. A native collision-handling branch may adjust the latter; it has not been validated against the live UI.

All **1,657 prefix-config rows**, including the **92** statically verified multi-ID arrays and the generic-prefix fallback, were reused without inventing new IDs.

### Important correction to earlier assumptions

Two distinct saved Ability instances with Base ID `81001`, Grade 2 and identical ordered prefix IDs `[1,1,1,1,26]` have different *raw numeric prefix levels*. The v0.7.3 selector computation produces identical candidate checksums for both, consistent with `GetTotalValue` reading the **prefix configuration number** and **Base ID**, rather than raw prefix-level values.

This **does not** prove that the final UI text of the two books is identical, nor that their gameplay effects are the same. It shows only that this particular name-selector path does not depend on the raw values.
