## Breakthrough: all three GetLevel arguments accounted for

`MartialInfoData.get_level` invokes **virtual slot 5** on its category-specific info object. Three classes all call the same `ConfBattleSkillLevel.GetLevel` at VA **`0x52bfee4`**, but load the second input from their respective configuration item class:

| Manual info class | Method VA | First input | Second input | Third input |
|---|---|---|---|---|
| `SkillInfoData` | `0x584109c` | `get_grade` vtable slot 11 (`+0x1e8`) | `ConfBattleSkillAttackItem.gradeMin`, item `+0x34` | cached prefix-list Count |
| `AbilityInfoData` | `0x5840a50` | same getter slot | `ConfBattleAbilityBaseItem.gradeMin`, item `+0x2c` | cached prefix-list Count |
| `StepInfoData` | `0x584167c` | same getter slot | `ConfBattleStepBaseItem.gradeMin`, item `+0x34` | cached prefix-list Count |

The `get_grade` slot assignment is evidenced in IL2CPP metadata type/method definitions for all three classes and the virtual call opcodes. The `gradeMin` field positions are evidenced by the native item constructors and exact metadata field names. All three methods transfer the third argument from the cached prefix-list Count to the common Level evaluator.

The key is `delta = actual manual Grade - category-specific gradeMin`; the common evaluator selects a Level threshold based on delta and **prefix Count** from the six native rows recovered in v0.5.8. This corrects the earlier overgeneralization that `SkillInfoData` alone handles all 183 manuals.
