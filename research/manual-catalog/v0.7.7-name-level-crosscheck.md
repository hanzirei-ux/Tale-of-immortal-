### Why BaseID + Grade is inadequate

For the generic Ability `81001` with Grade 2, sample instances reconstruct to **Level 2, 3 or 4**, depending on the prefix list. For `62111` (Heavenly Icy Eye) with Grade 2, the three sample instances reconstruct to **Level 3 or 4**. This is a cross-instance result, not a live UI observation. Therefore the DEX catalog must keep **Grade, Level, prefixCount, and instance-specific identity separate**.

## Validation boundaries

The previous work can compute conditional English name candidates and numeric Levels from original game configuration, but **this is NOT a verification against the title/Level actually displayed in Android**. The conversation did not contain a game screenshot with a fully identifiable manual and directly observed name + Level + Grade/prefix attributes. Public wiki mentions the existence/spelling of base skills but **does not identify an instance in the user's save**, and cannot establish an individual generated book title/Level. No title or Level is marked UI-confirmed.

To confirm, inspect one or more manuals in **the same save** used to extract `DataUnit.cache`: capture the book title, visible Grade and Level, and an affix/attribute view to disambiguate duplicate Base ID+Grade combinations. Align using the **private** `ui_validation_shortlist_14_PRIVATE.csv` included in the chat package. Only then label `CONFIRMED` or `MISMATCH`.
