## New finding: `EN_TEXT` is not necessarily a usable English label

On the v0.8.3 exact-key index of 810 metadata name keys:

| Classification | Keys |
|---|---:|
| English-column component candidates, no Han / placeholder | **681** |
| Chinese text remains in English column | **118** |
| Literal `???` placeholder | **5** |
| No exact entry in compiled native locale table | **6** |
| Total | **810** |

All five placeholders are native strings attached to keys `skill_name_middle110011` through `skill_name_middle110015`. These must be treated as unavailable names, not as translated English titles.

The **681** English-column component candidates contain **603 distinct strings**: **56** strings occur at multiple keys, affecting **134** localization keys. Examples include repeated `Sword Flurry`, `Decisive Strike`, and `Blasting Thunder`. Key identity and per-instance identity must never be collapsed by display text.

Prefix dictionary audit covers **2,284** entries from five families: `prefixNameS` **496** (English-column text without Han), `skillPrefixName` **1,584** (Chinese fallback), `stepPrefixName` **78** (Chinese fallback), `skill_name_first` **63** (Chinese fallback), and `skill_name_second` **63** (Chinese fallback). Those families are not interchangeable; do not concatenate them indiscriminately into full manual titles. Static locale text alone does not confirm how a particular save instance appears in the UI.

## Exact-key join policy

A separate private research package contains a read-only Python utility that joins source rows by exact localization key, preserves all original Grade, Level, Realm, Martial Type, BaseID, ordered prefix and instance fields, and reports missing/placeholder/untranslated keys without guessing. Its `--strict-183` option requires exactly **183 rows and 71 distinct keys**, preventing a partial sample from being mistaken for the previous complete dataset. One test uses a clearly labeled **synthetic** 183-row fixture; it is not real player inventory.

**28/28 offline tests PASS** against v0.8.3 source index.
