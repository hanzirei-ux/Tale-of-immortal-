## Corrected Grade semantics (important erratum to the earlier v1.1.1)

The previous v1.1.1 report claiming **652 item-quality Grades** is **incorrect and superseded** as a general quality-grade claim. A more rigorous object-field/constructor-argument audit establishes different meanings for fields sharing the name `grade`:

- **34 Rings**: `ConfRingBaseItem.grade` actually stores the **Ring Item ID** and matches the Ring ID for all 34 entries; **not an ordinal quality grade**.
- **1,458 Pill constructor calls**: `ConfItemPillItem.grade` raw values are **0 (1,343 calls); 50, 150, 350, 620 and 980 (23 calls each)**. Values are **not** quality Grade 0–10 or displayed G1–G6. Exactly **1,456** Pill calls join configured Item IDs; two do not and cannot be treated as callable item records.
- **56 Mounts**: `ConfItemHorseItem.grade` is a distinct 1–10 native field; no same-instance Android UI Grade validation yet.
- **104 Rarity Material config records** from a separate previous audit have a field called `grade`, but mapping it to general Realm/Rarity or displayed quality still requires independent validation.
- **Native Item `level` (1–6)** is a separate source field for the 3,309 Item ID catalog and must not be universally renamed Grade, Realm or Rarity.

The old aggregate 652-record Grade claim is **not safe for Mod Menu filters**. Keep raw-source fields with their class-specific labels and explicit confidence/status.
