## Source-backed numeric Outfit sex hint, not confirmed UI mapping

Original IL2CPP metadata type index **6369** declares enum `UnitSexType` with static members `None`, `Man`, and `Woman`. Matching field-default data decodes to respective signed integers **0, 1, 2**. The distinct `ConfClothItemItem` type index **4034** has an **integer** field `sex`, and all **295** real Outfit configs use **sex_code=1 (147 rows)** or **sex_code=2 (148 rows)**. Each code also consistently selects model ID 31001 or 32001 respectively. This numerical relationship **supports** displaying the hints `Man?` and `Woman?` in an offline picker but **does not prove** that `ConfClothItemItem.sex` is typed or interpreted as `UnitSexType` by the Android Outfit UI. Its raw codes remain visible; there is **zero live UI verification**.

Separately, metadata enum `EColor` (type index **8915**) has members `Red=0`, `Purple=1`, `Green=2`; there is **no proof that it supplies Outfit colors**, whose `ConfClothItemItem.color` values are 1/2/3. **No color names are assigned.** No screenshot, direct runtime binding, or rendered color previews have been checked.
