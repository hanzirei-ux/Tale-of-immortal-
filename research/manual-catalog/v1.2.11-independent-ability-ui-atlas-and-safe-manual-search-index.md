# Tale of Immortal Android — v1.2.11 Independent Ability UI Atlas and conservative Manual/Skill search index

**Date: 2026-11-03. Read-only research.** Original user-supplied game binaries, 17 AssetPack archives, private saves, APK, `classes2.dex`, and functioning Mod Menu v0.3.6 remain unchanged.

## New verified UnityFS resource sources

The original `assetpack_008.zip` contains **five additional relevant UnityFS sprite-atlas bundles** that were not part of the previous v1.2.4-v1.2.10 SkillAttack/Step name-to-Sprite joins. Their original block info and data were decoded using the aligned UnityFS v8 header and LZ4 blocks. Unique **serialized AssetBundle resource paths ending in .png** were enumerated directly from each original serialized node:

| Atlas bundle | Unique serialized PNG asset paths |
|---|---:|
| `spriteatlas_commonabilityiconspriteatlas.ab` | **14** |
| `spriteatlas_commontaoistheartskillicomspriteatlas.ab` | **12** |
| `spriteatlas_commontaoisthearticomspriteatlas.ab` | **67** |
| `spriteatlas_commontaoistseedicomspriteatlas.ab` | **21** |
| `spriteatlas_potmonlifeskilliconspriteatlas.ab` | **239** |
| **Combined** | **353** |

The dedicated **CommonAbilityIcon** resource catalog contains exactly **eight `type_1`–`type_8`** and **six `di_1`–`di_6`** named PNG resource paths.

**Critical proof boundary:** These are **serialized AssetBundle path names** in real UnityFS data. This inspection did **not** decode texture pixels into PNG, verify every Sprite's specific packed rectangle, or prove that `type_5` means Ultimate / Mind Skill or that `di_1` is a grade/realm. Most importantly, the 14 Ability icons are **not** now directly joined to any particular AbilityBase BaseID. All **0/81** AbilityBase icon joins remain unverified. The `className` array stored in AbilityBase field `+0x20` was previously proven to be a 32-bit-element array, **not** a static icon key.

## Consolidated, namespaced native-key candidate index

The existing complete v1.2.10 CSV was read without changing old rows or fields. It has **1,664 unique (constructor family, BaseID)** identities. The new private **read-only index** filters only records whose constructor `name_key` is non-placeholder:

| Proven native constructor name-key status | Count |
|---|---:|
| SkillAttack `skill_name_middle...` | **805** |
| SkillAttack auxiliary `chickenskillname_...` | **37** |
| StepBase native name keys | **15** |
| AbilityBase native name keys | **77** |
| **Total non-placeholder constructor name-key rows** | **934** |

Of these 934 rows, **856** have previously verified native icon-key-to-Sprite-name evidence (**841 SkillAttack + 15 StepBase**); **78** do not (**77 AbilityBase + 1 SkillAttack**). **None of the new independent UI atlas paths is used to manufacture a BaseID association.** The 934 count differs from the historical v1.0.6 **860 named constructor templates** because naming coverage and inclusion criteria have evolved (including 37 explicitly auxiliary chicken key records). **934 is not a count of obtainable inventory Manuals, English full titles, or working Add Manual choices**; key strings are only localized name components.

- Original pinned `libil2cpp.so` and `global-metadata.dat` SHA-256 identities were verified before reading old data.
- Counts validated for five decompressed UnityFS bundles, 353 unique `(bundle,path)` entries, 14 Ability UI resource names, 1,664 preserved namespaced constructors, 934 name-key candidates, and 856 versus 78 icon status.
- Private deliverables: **353-path CSV**, five-atlas summary, **934-row searchable conservative constructor index**, separate **14-path Ability UI file**, local HTML search page, read-only regeneration scripts, a compact XLSX workbook and a CRC-checked ZIP. The HTML's JavaScript passed `node --check`. The offline search performs **no** Add Manual or JNI calls.
- The separate full Item catalog remains **3,309 native Item IDs** including 395 Gear, and **60 English item-name gaps**. Those are unchanged by this research.
