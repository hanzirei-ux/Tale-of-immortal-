## Independent source-based reproduction of native PrefixValue rows

The original pinned `libil2cpp.so` (SHA-256 `c477a5637b89f78ca449ff65ad4c9137296ba680923b602db50831ecb5901099`) has exactly **1,657 direct ARM64 `BL` calls** to the native constructor **`ConfBattleSkillPrefixValueItem..ctor` RVA `0x2833608`** in the configuration initializer. The actual constructor instructions were inspected to verify field placement, independently of the previous v0.9.9 report:

- Native argument `w1` holds consecutive configuration indices 1–1657.
- Argument `w2` is saved to `+0x18`: metadata field `skillType`.
- Argument `x3` is saved to `+0x20`: metadata field `skillID` (array).
- Argument `w4` is saved to `+0x28`: metadata field `number` (prefix number).

The array allocation immediately preceding each constructor was decoded through original `BL 0x2615a20` calls:

| Source-proven skillID array length | Native constructor rows |
|---:|---:|
| 0 | **15** |
| 1 | **1,550** |
| 3 | **72** |
| 12 | **20** |
| **Total** | **1,657** |

All **1,550/1,550** one-element arrays were reproduced **directly from original ARM64 `str w*,[x20,#0x20]` writes**, with correct wide MOV/MOVK/ADD constant propagation, instead of BaseID-number guesswork. These give **195 unique BaseIDs** and 1,550 unique `(skillType,BaseID,number)` source rows. Exactly **92** multi-element arrays were confirmed to be populated through a separate static-data helper, but **their per-element payload is not rederived/claimed in this milestone**. The other 15 arrays are empty/generic.

Native `skillType` code frequencies **across all 1,657 constructor rows**: code 1 = **257**, 2 = **581**, 3 = **132**, 4 = **392**, 5 = **197**, code **11 = 98**. The field named `skillType` is an original *int* in `ConfBattleSkillPrefixValueItem`; it must **not** be conflated with the distinct `MartialType` enum that only defines 0..5.
