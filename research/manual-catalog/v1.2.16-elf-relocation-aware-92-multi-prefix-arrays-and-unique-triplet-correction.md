# Tale of Immortal Android — v1.2.16 ELF-relocation-aware multi-prefix arrays and distinct-triple correction

**2026-11-03 | Read-only research.** The original user-supplied APK, DEX, Unity AssetBundles, `libil2cpp.so`, `global-metadata.dat`, saves and functional Mod Menu v0.3.6 were **not** modified. No APK/DEX patch, native Add Manual call, Android runtime hook or visual game test was performed.

## Original-binary methodology

The prior v1.2.15 audit proved **1,657** direct ARM64 calls to `ConfBattleSkillPrefixValueItem..ctor` and decoded all **1,550** one-element `skillID` arrays. This milestone independently revisited **all 92** multi-element array initialization sites:

1. Read the original ELF's `.rela.dyn`, applying **`R_AARCH64_RELATIVE`** relocation addends to initially-zero GOT pointer slots in static register tracing. Treating the raw ELF GOT zero as a null runtime pointer gave a demonstrably wrong result.
2. Trace actual `ADRP/LDR`, preserved-register transfers and the `x1` field-reference argument at each of **92** direct `RuntimeHelpers.InitializeArray` calls.
3. Join every recovered tagged `FieldInfo` reference to its actual v31 `global-metadata.dat` `fieldRefs`, field-definition owner and static-default byte offset, without assigning name suffixes or assuming BaseIDs.
4. Preserve the original constructor `skillType`, prefix number and exact array length; interpret the field-default storage strictly as **32-bit raw bit patterns**. Do not automatically treat all bit patterns as valid skill IDs or claim verified Android runtime values.

Both pinned source SHA-256 identities matched previously published baselines:
- `libil2cpp.so`: `c477a5637b89f78ca449ff65ad4c9137296ba680923b602db50831ecb5901099`
- `global-metadata.dat`: `9be3762476a87e8be23e3fa589b44f084027a5c7f1ff78b9be5f013fb5d131b3`

## Important correction: 2,021 source slots are not 2,021 distinct triples

Counting all source positions in the native `ConfBattleSkillPrefixValue` data yields:

- **1,550** single-ID source positions,
- **456** multi-array element positions,
- **15** source rows with empty arrays / generic fallback, represented separately using the prior audit's technical `skillID=0` convention;
- **2,021 total positions**, not distinct records.

Of the **456** multi-array positions, only **421** distinct raw `(skillType, 32-bit value, prefixNumber)` triples occur. **35 positions** repeat a triple already present in another multi-array position. Neither the 1,550 single-element triples nor the 15 generic fallback triples overlaps those 421 under the same comparison.

Therefore the exact raw **distinct technical triples are 1,550 + 421 + 15 = 1,986**, not 2,021. This **corrects the historical v0.9.9 wording of '2,021 unique expanded'**: 2,021 is the expanded count of source slots. The 1,986 figure is still **not** a number of player Manual books or proven usable prefix configs.
