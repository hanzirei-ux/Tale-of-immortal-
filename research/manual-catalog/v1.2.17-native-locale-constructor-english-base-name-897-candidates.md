# Tale of Immortal Android — v1.2.17 English base-name joins from actual native localization constructors

**2026-11-03 | Read-only original-binary research.** No APK, `classes2.dex`, `libil2cpp.so`, `global-metadata.dat`, game save, AssetBundle, or functional v0.3.6 Mod Menu feature was changed.

## Native localization proof, not web-name inference

The matching, SHA-256-pinned original Android `libil2cpp.so` and `global-metadata.dat` were re-extracted from the user's previously supplied archive, with exact source hashes checked:

- Native `libil2cpp.so`: `c477a5637b89f78ca449ff65ad4c9137296ba680923b602db50831ecb5901099`.
- `global-metadata.dat`: `9be3762476a87e8be23e3fa589b44f084027a5c7f1ff78b9be5f013fb5d131b3`.

A read-only ARM64 trace scanned **56,259 direct calls** to the compiled localization-row constructor (`0x65AED20`) within the executable region. The original initializer supplies the **key string literal via argument `x2`** and the **English-column literal via argument `x5`**. Pointer provenance was recovered from `ADRP/LDR` and ELF **`R_AARCH64_RELATIVE`** relocation addends, then exact string literals decoded using `global-metadata.dat`. Constructor register sourcing, not BaseID-suffix guesses or a web translation, determines each join.

A direct example is the original constructor at `0x65CBFE8`: `x2=skill_name_middle11412` and `x5=Aether Fire`. Independent examples include the native string row for `skill_name_middle7131` yielding `Bone Etching Wind` and `skill_name_middle7317` yielding `Missiles of Flame`.

A second pass traced longer-lived callee-saved register sources for the small group of otherwise unresolved English-column arguments. **Special exception:** at `0x65CC970`, the original instructions use `sub x5,x3,#0` to copy a Chinese-language string into the English argument for one candidate; that string is correctly labeled **fallback Chinese** rather than a translated English name.
