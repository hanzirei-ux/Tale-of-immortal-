## Crucial remaining step: native checksum selectors, not arbitrary prefix-name indices

An instance stores ordered **numeric prefix IDs and values**, but the game's English title prefix names are looked up through a separately calculated pair of **checksum-based selector indices** into the two 200-entry English prefix-name groups. The *saved prefix number* is **not itself** a direct row ID in the 400-entry prefix-name table. Assigning a group-1/group-2 title name from prefix numbers or BaseID alone would manufacture unsupported titles.

The older aggregate research v1.0.0 reported **183 conditional full-title candidates** and offline Levels based on a previously derived algorithm; however, that older private per-instance selector output was not available during this reproduction. This new v1.2.19 package **deliberately leaves per-instance prefix selector indices and final-title columns blank**, rather than claiming to have rederived the actual native checksum results.

- **183/183 native English base-name components verified**.
- **0 newly rederived full two-prefix instance titles** in v1.2.19.
- **0 titles and 0 individual Levels directly verified on Android UI**.
- Saved Grade and runtime Level, Realm, Rarity and inventory ownership remain distinct/unverified.

A new Android-friendly **offline 183-instance search/browser** displays exact saved prefix ID/value sequences and can produce only **explicitly labelled manual-simulation** combinations selected from the original 400 English name rows. It does not claim these are the saved instance's title, and it performs **no gameplay/DEX/JNI operations**.
