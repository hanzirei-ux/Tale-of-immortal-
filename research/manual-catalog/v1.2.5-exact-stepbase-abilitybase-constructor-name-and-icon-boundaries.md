# Tale of Immortal Android — v1.2.5 Native StepBase and AbilityBase Catalog

**Date: 2026-11-03. Read-only audit**, using the same user-provided SHA-256-pinned original `libil2cpp.so` and `global-metadata.dat` as v1.2.4. The user’s APK, Mod Menu v0.3.6, DEX, SO, saves, and AssetBundles were not changed.

## Exact constructor identification and tracing

Two additional native constructor families were located and examined, with direct ARM64 `BL` target checks, `w1` BaseID arguments and `x2` original localization name keys:

| Constructor family | RVA of original constructor | Direct native initializer calls | Name-key status | Icon-key status |
| --- | --- | ---: | --- | --- |
| `ConfBattleStepBaseItem` | `0x2869904` | **15** | 15/15 name-key literals recovered | **15/15** direct `x3` key joins to real Step Sprite objects |
| `ConfBattleAbilityBaseItem` | `0x5a7c82c` | **81** | **75 non-placeholder**, 4 literal `0`, 2 unresolved argument pointers | No exact native icon-key proof; leave all unknown |
| Previous `ConfBattleSkillAttackItem` (v1.2.4) | `0x5d4eccc` | **1,568** | 805 standard + 37 auxiliary `chickenskillname_` + 726 `0` | 1,426 direct matches to Skill/Step Sprite objects |
| **Combined constructor records** | | **1,664** | Not 1,664 English manual titles | Not 1,664 addable manuals |

The raw Step initializer calls occur at `0x286a33c` through `0x286ae48`, while Ability initializer calls occur at `0x5a7d21c` through `0x5a8025c`. The binary source identity was checked using the existing pinned SHA-256 baseline.

### Step name/icon evidence

All **15 Step** records have separate constructor `x2` name keys and **`x3` icon keys** matched to one of the **16 real Sprite objects** in the game's `spriteatlas_commonstepiconspriteatlas.ab`. **12 distinct icon names** are used, because some Step BaseIDs reuse images. Examples:
- `510011`: `stepName1` → `tiaozhan`;
- `510021`: `stepName2` → `qiangci`;
- `510031`: `stepName3` → `yujian`;
- `510121`: `stepName12` → `huanying`.

This proves exact native name/icon token joins plus Sprite names, **not** that their pixel images were decoded to PNG or their complete manual titles verified in Android UI.

### Ability: recovered names are not icons

**75/81 Ability** constructors contain exact non-placeholder `x2` localization name keys. They include `ability_name_first...`, `ability_name_last...`, and `ability_name_...` variants. Four calls pass native `0` names; two could not be resolved conservatively. Unlike Step and SkillAttack, no direct comparable **static icon name-key** was proven for this constructor: its `x3` argument is not an independently verified Sprite name, and inventing one from BaseID or a numeric substring would be incorrect.

## Reconciliation with v1.0.6's 860 named templates

The earlier figure **860** = **804 SkillAttack + 15 Step + 41 Ability** under earlier name tracing criteria. The updated tracing now recovers **805** standard SkillAttack name keys (+37 *auxiliary chicken* family), **15** Step name keys and **75** Ability nonplaceholder keys. They have **different coverage and classification criteria**; do not present their sum as 895 selectable manuals nor replace the historical 860 without a verified definition of usable manual templates.

The 1,664 constructor records represent **1,658 distinct bare numeric BaseIDs** due to overlapping BaseIDs across constructor families. The private combined catalog uses **(constructor-family namespace, BaseID)** as its unique primary key so no unrelated record overwrites another. Ordinary Item IDs remain in a distinct namespace.

## Validation, privacy, next steps

Private outputs: **1,664-row name/icon-status index**, 15 Step rows, 81 Ability rows, a separated new-name-key subset, an offline searchable HTML, test/asserted summary, reproducible read-only ARM64 tracing script, and a filterable Excel workbook. Source hashes, 15/15 Step Atlas matches, 75/81 nonplaceholder Ability keys, 4 zero, 2 unresolved, 1,664 namespaced unique records and ZIP CRC were validated.

Not verified: complete English Manual titles, item-specific Manual Grade/Realm/Rarity, ability icons, actual ASTC PNG pixels, obtainable skills, native Add Manual action, DEX packaging or Android gameplay behavior. The user’s existing functional Mod Menu must remain unchanged until tested.

**Privacy:** Original game binary, localization rows, comprehensive native ID/name/icon tables, saves, user files and the private ZIP were **not uploaded** to this public GitHub repository. Only this aggregate/methodology report is published.

**Next:** Identify Ability icon retrieval from actual UI/runtime method consumers (not guessed), and check the missing locale keys against exact game localization sources. Preserve the historical manual-type distinction and only integrate browse/search into the user's working DEX after validation.
