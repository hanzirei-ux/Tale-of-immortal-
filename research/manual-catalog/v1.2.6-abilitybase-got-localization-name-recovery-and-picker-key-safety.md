## Why Ability icon mapping remains unknown

At the **81** exact constructor calls, source disassembly shows `mov x3,x20` before the `ConfBattleAbilityBaseItem` call; at independently verified examples x20 was derived from an immediately preceding runtime helper's return value, **not** an x3 tagged static Sprite name literal. The original constructor stores x3 to object offset `+0x20`. This does not establish the runtime object's semantic purpose or a usable icon key, so **0 AbilityBase icon mappings are claimed verified**. The 15 StepBase Sprite matches and 1,426 SkillAttack Sprite matches remain unchanged.
