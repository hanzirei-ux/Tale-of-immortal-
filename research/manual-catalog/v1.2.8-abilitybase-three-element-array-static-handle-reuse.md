# Tale of Immortal Android — v1.2.8 AbilityBase x3 static-array reference reuse

**2026-11-03 | Read-only native analysis.** No APK, DEX, `libil2cpp.so`, game save, or AssetBundle was changed.

## Evidence from original ARM64 binary

The previously verified `ConfBattleAbilityBaseItem` initializer has **81** constructor calls, each receiving an `x3` array object. As confirmed in v1.2.7, **40** arrays have length 0 and **41** arrays have length 3. At each of the 41 nonempty initializations, the original instructions make a direct `BL 0x760ADA8` call with `x0` holding the array, `x1` holding a field-metadata handle, and `x2` zero. The x1 value comes from a relocation-backed pointer dereference before the helper call; it is **not a Sprite name or manual BaseID**.

A new register/relocation trace across the exact original initializer instructions recorded the concrete source of `x1` at **41/41** such calls. It found **13 distinct relocation-resolved handle storage addresses**.

| Reference reuse shape | Handles | Constructor calls | Exact observed structure |
|---|---:|---:|---|
| One handle shared among five | **1** | **5** | BaseIDs 81001/82001/83001/84001/85001 |
| One handle shared among three | **12** | **36** | BaseIDs 860xx/870xx/880xx share the same handle when suffix xx is identical, for xx=01–12 |
| **Total** | **13** | **41** | All three-element arrays accounted for |
| Empty arrays | — | **40** | No corresponding static-data helper call |

**Example:** 86007, 87007, 88007 all pass the same field-metadata reference to their array initializer; 86008, 87008, 88008 use a different shared reference. This is a **native-source identity grouping only**, not proof that the gameplay effects, raw array element values, or rendered icons are equivalent.

Original file SHA-256 checks were repeated for the pinned `libil2cpp.so` (`c477a5637b89f78ca449ff65ad4c9137296ba680923b602db50831ecb5901099`) and `global-metadata.dat` (`9be3762476a87e8be23e3fa589b44f084027a5c7f1ff78b9be5f013fb5d131b3`). The direct helper, constructor, and array allocation calls were separately counted: 41, 81 and 81. The 13 handle groups were validated with exact BaseID membership and no unassigned length-three arrays.

## Catalog continuity

The private v1.2.8 research outputs extend the **1,664-record** three-constructor index with additive reference-group columns; **all prior column values and composite (constructor family, BaseID) identities are unchanged**. The 81 AbilityBase name and prior proven icon status are preserved. Neither previously confirmed **1,426 SkillAttack** nor **15 StepBase** sprite associations is modified. The existing historical **860 named manual template** scope is a different reporting definition, not an additional 860 items.
