## Important: x3 belongs to `className`, not an icon

The native `ConfBattleAbilityBaseItem` constructor (RVA `0x5a7c82c`) saves argument `x3` at object offset `+0x20`. Its exact metadata type definition contains `name` then **`className`** in the corresponding field order. A neighboring native array-clone routine copies individual **4-byte elements** from this field. These observations support an array-valued `className` parameter, **not** a static Sprite-name argument. The exact meaning of these numeric class-related entries in gameplay remains unknown.

The v1.2.7/v1.2.8 source counts remain:
- 81 AbilityBase constructors: **40** arrays of length 0, **41** of length 3.
- 41 nonempty-array initializer calls use **13 distinct native metadata-field handles**, reused as one 5-call group and twelve 3-call groups.

## New exact FieldInfo provenance

The original compiled handle storage contains tagged metadata tokens, for example `0x8000002f`, whose source index can be resolved through the **version-31** `global-metadata.dat` `fieldRefs` table. Each matched `fieldRefs` owner type is resolved through a genuine metadata type definition, and the referenced field's name and field-default record are checked by their actual indices. No candidate is derived by ID suffix alone.
